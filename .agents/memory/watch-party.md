Watch parties join Nuvio's own parties (built 2026-11-11, ADR-0051). Layout: `internal/nuvio/party.go` (watch_party_* RPCs), `internal/nuvio/realtime.go` (Phoenix channel client), `internal/backend/party.go` (`Parties` + type aliases), `internal/party` (Service, `rules.go` sync rules, `session.go`, `playback.go` follow-the-player + gate, `chat.go`, `who.go`). Frontend: `lib/party.ts`, `components/party/*`, `routes/party.tsx`, `shell/party-status.tsx`, player sheet on W, picker `PartySources` card.

**Why:** it's the user's ask to match Nuvio; parties mix Peli and Nuvio clients, so Nuvio's thresholds and payloads are copied as behaviour (re-implemented, Nuvio's code is GPL-3).

**How to apply:**
- Live answers 410 on `/realtime/v1/websocket` without `nuvio_realtime=1` in the query. A join's `ref` must equal its `join_ref`.
- The RPCs exist only on api.nuvio.tv, not self-host: they're in `contract_test.go`'s `liveOnly`, checked by `set -a; source spikes/nuvio-backend/.env; PELI_NUVIO_LIVE_WRITES=1 go test -run 'TestLiveParty|TestLiveTwoMembers' ./internal/nuvio/ ./internal/party/` (creates a party on the real account, ends it, signs out). `update`/`leave`/`end` answer only `{ok:true}`; non-host gets `not_host`.
- User pauses/seeks/speed go through `player.GateWith(players, party.GateOf(parties))`; party corrections use `player.DirectOf` (no gate). New player controls must use the gated methods.
- `Party.Watch(null)` is sent from `PlayerPage` unmount, not `PlayerFile`, so the next episode moves the party for the host.
- Frontend tests: `@bindings/party` is mocked in `src/test/setup.ts` (unmocked, the Wails call goes through stubbed `fetch` and breaks `serve` helpers). `player.test.tsx`'s `Events.On` mock now keeps a Set of listeners per event (root and player both listen to party:notice). Fixtures: `partyState`/`partyMember` in `src/test/fixtures.ts`.
- Baseline on 2026-11-11 before this work: 47 frontend tests and Go tests in anilistaddon, backend, player (picture), plugins, store, torrent already failed; compare against that, not zero.
- Not tried with a real Nuvio app in the party yet; no deep link (`peli://party`) yet.
- **In both builds since 2026-11-21 (ADR-0063).** A party carries only play/pause/seek/chat over Nuvio's websocket, so party is out of `notOnIOS` and `internal/party` and `github.com/coder/websocket` are now *required* in the iOS deps (`ios_boundary_test.go`); pion, anacrolix, goja, plugins, updates and firstmouse stay out, and the iOS CI symbol grep dropped `party`. The service is shared now: `main.go`'s `peli` struct owns `parties`, created in `newPeli` right after the player and registered in `services()` after it; `extras` lost its field and `main_desktop.go` lost its lines.
- **iOS player gate:** `service_ios.go` has `GateWith`/`Direct`/`DirectOf` and gated `SetPaused`/`Seek`/`SeekBy`/`Scrub`/`SetSpeed`, mirroring desktop; `gate_ios_test.go` (`ios` tag). Bound methods and cgo unchanged.
- **Suspension:** `party.Away`/`party.Back` in `internal/party/suspend.go`, plain functions called from `main_ios.go` (Away in `enterBackground` right after `engine.Suspend`; Back in `becomeActive` via `safego.Go`). Away closes the channel on purpose, keeps the session and seat, sends no leave, a host away doesn't end the party; Back rejoins by code: ended/not found → `ended` notice, `removed` → `removed`, network error → keep the session and reopen the channel, same seat → reopen + `applySnapshot` + `catchUp` through `Direct`, lost seat → new seat carrying playback (3 tries, 1 s apart). `session.go`'s `begin` now uses `openChannel`. Tests: `suspend_test.go`.
- **Touch entry:** `TouchTopRow`'s 44 pt button (Users icon, "Watch party", a dot while in a party) opens the same `openParty()`/`PartySheet` as W; on `useCompactShell()` the sheet is a BottomSheet (tab bar hides, `min(44rem,85dvh)`, `pb max(safe-area,--keyboard-h)`, chat list stops `touchstart`). `"w"` out of `iosKeysOff`, so an iPad keyboard opens it. **No relaunch rejoin:** sessions are in memory only, so a relaunch after a kill starts with no party.

- **Reactions (2026-11-21, ADR-0051's addendum).** `internal/party/reaction.go`: `REACTIONS` (😂 ❤️ 🔥 😮 😢 👏 🎉 🍿, in that order), `SendReaction(emoji)` (outside the list → `CodeInvalid`; no party → `CodeNotInParty`; 250 ms per member, extras dropped with a nil error) and `onReaction` for the incoming `"reaction"` broadcast (the same 250 ms window per sender), reached from `session.go`'s broadcast switch. The wire is only `{emoji, member_id, sent_at}`; the channel is joined `self:false`, so Go emits the sender's own `party:reaction` with `Mine: true` from `SendReaction` (`EventReaction`, `Reaction{Emoji, MemberID, Name, Mine, At}` with JSON `emoji`/`memberId`/`name`/`mine`/`at`, the name resolved from the session). **No burst on click:** player-page mounts only `PartyReactionLayer`, which bursts from the event, so a refused emoji or no party shows no confetti. Nuvio's clients ignore the unknown broadcast, so reactions are Peli-to-Peli: a friend on Nuvio's apps neither sees nor sends one.
- **Reaction and dock layout:** `lib/confetti.ts` (pure physics), `components/party/emoji-confetti.tsx` (`EmojiConfetti` plus a module-level `burst(emoji)` that drives whichever overlay is mounted, a no-op when none is), `components/party/reaction-bar.tsx` (`ReactionBar`, the 8 buttons; `PartyReactionLayer`, the overlay + quiet name label), `lib/party.ts` (`REACTIONS`, `reactionEvent = "party:reaction"`, `useSendReaction`, `usePartyReactions`), `components/party/party-dock.tsx` (`partyDockWidth = "22rem"`, `usePartyDock()`, `PartyDock({ onClose })`).
- **Where the reactions live (moved into the chrome 2026-11-21):** the bar is not in the chat any more; `party-chat.tsx` is the messages and the composer. `player-page.tsx` draws `<ReactionBar chrome />` a row above the seek bar whenever `party && !mini` (so never in the mini player): in the desktop/iPad dock, inside the `controls` div so it fades with the rest, and in the touch chrome's bottom bar above `seek-row`, where it also takes the scrub `faded` (opacity, so the timeline doesn't jump). `chrome` is the look: a glass capsule (`material-media`, `mx-auto h-10 w-fit`), 1.25 rem emoji, plain white, the buttons pinned by `pointer-coarse` hit areas so 8 fit 320 pt at `icon-sm`. The dock makes room rather than the row spilling: the root sets `--party-row:2.75rem` in a party (0 otherwise) and `--dock-h`, `--touch-chrome` and `--above-bar` all add it, and `liftToClear`'s `covers` gains `reactionRowRem` (on the dock `dockClearanceRem` 8 + it; on the touch chrome `touchChromeRem` + it), so the skip and next-episode cards, the prompts and the subtitles stay clear. A click stops propagating (no pause, no full screen) and a pointer's click blurs the emoji it landed on (`event.detail > 0`, so a mouse never keeps the focus but Enter does), so Space stays the pause while Tab + Enter still sends. Tested in `routes/player.test.tsx` (party, mini, the click's `SendReaction` without `SetPaused`, and the touch row with `onCompactIOS()`). The standalone `routes/party.tsx` page still shows `PartyChat` in a card, so it is the one place a party now has no reactions: only the player's chrome has them.
- **The dock ("Keep open"):** `partyDock` in `DeviceSettings`, per device; desktop and iPad only, since `usePartyDock().available` is false on the compact shell and `docked` is then always false, so the iPhone keeps ADR-0063's bottom sheet and hides the option. `--party-dock-w` (22rem docked and open, else 0) is set on the player root. The video shift is `Player.SetVideoInset(rightPx)` → mpv's `video-margin-ratio-right` from the window width, recomputed on resize, **ungated** like `Direct` (it moves the picture, not playback, so it publishes nothing and the host can't refuse it). Undock leaves the party open (the sheet shows again); `onClose` hides the panel and keeps the setting.
- **Test mocks for the two:** `SendReaction` is in `src/test/setup.ts`'s `@bindings/party` mock, and `partyReaction()` sits next to `partyState`/`partyMember` in `src/test/fixtures.ts`. setup.ts has no `@bindings/player` mock and no `@wailsio/runtime` one, so player mocks are per file: `routes/player.test.tsx`, `routes/streams.test.tsx` (both replace `Service` outright and render the player), `routes/settings.test.tsx` and `components/player/stats-overlay.test.tsx` (spread the actual one), `components/shell/command-palette.test.tsx` (`loading({})`). `SetVideoInset` has to be on the mocks that replace `Service` and draw the player.
- **Gotchas from the merge (2026-11-21):** a new Wails event's payload type reaches `@bindings/party` only once it's in `service.go`'s `init` (`application.RegisterEvent[Reaction](EventReaction)`). Without that line, `Reaction` was missing from the bindings. `internal/player/inset.go` (+ test) is `//go:build !ios`, because `ios_boundary_test.go` allows only `service_ios.go` and `types.go` in `internal/player` on iOS (`service_ios.go` computes its own ratio). Layering: the confetti canvas is z-30 (the player chrome tops out at z-20, and menus and sheets are z-50), and the name label shares z-30 and comes later in the DOM. The reaction bar is a `<fieldset aria-label="Reactions">` (lint's prefer-tag-over-role), still queried as role group. `PartyDock` takes an optional `canShare`, the same value PartySheet gets. Unverified: a real two-device reaction, the dock on a real iPad, and the iOS margin-ratio path on a device.

- **Guests never pick a stream in the player ("player lockouts", 2026-11).** One flag, `isPartyGuest(party, media)` from `lib/party-pick` (pure, so no test mock): while it's true the Streams button and the `StreamSwitcher` sheet aren't rendered, `s` is out of `onKey`'s `once` map, `openSwitcher` returns at once (the button, S and the host's way out of a failure all go through it), `shortcuts.tsx`'s `playerShortcuts` became `playerShortcuts({ guest })` and drops the S row with the "In the Streams panel" group, and the failure overlay reads "Try another stream" and calls `useWatchWithParty()(party.media, true)` — the picker route, which auto-picks — instead of opening the sheet. The host keeps all of it. Tested in `routes/player.test.tsx` under `stream switcher › in a watch party`, with `partyState`/`partyMember` reshaped to the pilot's media (`type`/`id`/`videoId`) in both slots; `isPartyGuest`'s comparison is `partyWatches`'s, so currying a fixture's media into that shape is what makes a test a guest. No new binding calls, so setup.ts's `@bindings/party` mock needed nothing. The ⌘K palette has no stream command, so it needed no change.

- **A guest's picker picks the moment it opens (2026-11-21), so a test can't watch its address settle.** `useWatchWithParty(media, replace)` lands on `/streams/$type/$id` and `usePartyAutoPick` resolves, loads and goes on to `/player` from there — in one flush if a stream is served, so `waitFor(pathname)` for the picker times out at `/player` (a `userEvent` click flushes more than an `emit` does, which is why the eof and Play it tests disagreed). Assert the destination where the pick can't happen: `mocks.resolve.mockRejectedValue(new Error("no stream"))` before the click (as `routes/streams.test.tsx` does), then read `pathname`, `search.video` and `state.play`.
- **"Play it" for the party's next episode can't use `isPartyGuest`.** That one asks whether the party is on the file *playing*, so it is false when the party is on the next episode; `player-page.tsx`'s `partyNext`/`startNext` use the party's own check, `party && !party.isHost`, and skip the `NextEpisode` card so `usePreparedNext` never asks for that episode's streams. A guest without a party keeps its own card.
