Phase 5 of the player enhancements ([[player-picture]] has the model and plan; [[player-tracks]] and [[addon-subtitles]] are what it extends).

- **Second line (dual subtitles):** mpv 0.41 has no `secondary-sub-scale`, so `secondary-sub-visibility=no` is a session option and Go observes `secondary-sub-text` → `State.secondarySubtitleText`. The screen draws it (`components/player/second-subtitles.tsx`) in the main style at 0.7× size, above the main block. Hidden, mpv still decodes it (visibility only gates the OSD: `dec_sub.c`/`osd.c`). Not drawn in the mini player or while loading.
- **Tracks:** mpv marks the second track `selected` too; `main-selection` (0 main, 1 second) tells them apart. `Track.Selected` is now **main only**, `Track.Secondary` is the second, so `selectedId()` in the page needs no change. `Service.SetSecondarySubtitleTrack(id)` (0 = off) refuses the main track and picture codecs (`imageSubtitle`); `SetSubtitleTrack` drops the second line when the new main is that track. Every Load sets `secondary-sid=no` (in `LoadOptions.tracks()`, after the `props[3..5]` that TestSystemCaptions indexes). `Subtitle.Secondary` makes `AddSubtitle` use `sub-add … auto` (added, not selected) then set `secondary-sid`.
- **Placement (`lib/subtitle-position.ts`):** mpv's 720-line numbers as shares of window height (55 px face, 22 px margin, leading 1.15). `secondLine(height, {size, lift}, lines)` gives bottom px + base font. Main lines come from `lineCount(state.subtitleText)`, held between lines. It's an estimate: a long line mpv wraps isn't counted.
- **Picking:** Subtitles tab has a Main / Second line segmented control (only with ≥ 2 choices) that reuses the same list; the main track and picture tracks are disabled with a reason. Shift+C cycles file/added text tracks other than the main, then off. `Settings › Languages & subtitles › Second subtitle language` = `ProfileSettings.secondSubtitleLanguage`; `autoSecondary` picks (once per file, after the main subtitles settled) the file's own full track in that language, else an addon's; never next to forced-only main, never the main's own language. A manual pick of either line cancels the auto. After a reload (expired link) the second line is restored from `showingSecond`.
- **Nudges and saving:** R / Shift+R lift ±2 %, G / Shift+G size ∓/± 5 % (`nudgeSubtitles`, via the page's `subStyle` state → `Player.SetSubtitleStyle`). The auto-save of Style tab edits is **gone**: only the Style tab's "Save as my style" (`StyleSave` prop; absent in Settings, which keeps its own save) writes `ProfileSettings.subtitleStyle`. A fresh file (next episode, another stream) starts from the saved style again.
- **Lift that clears the controls:** while the controls show, `lifted = max(style.lift, liftToClear(windowHeight, mini))`, not the sum — the old complaint was a high lift staying high when the controls hid. The page sends `{...style, lift: lifted}` through one effect (so the profile lift isn't what mpv gets while the dock is up) and the second line follows `lifted`. Nudging and the Style tab show the raw lift (`nudgedAt` for 2.5 s, `panel === "style"`); R/G don't wake the controls. mpv moves instantly, so the overlay doesn't animate either. `sub-pos` doesn't move ASS subtitles that bring their own position unless the style's "Restyle styled subtitles" is on.
- **Picture subtitles (2026-11-23, "Dune looks low quality"):** a Blu-ray remux's "English [SDH]" is PGS (`hdmv_pgs_subtitle`), a bitmap. mpv 0.41 `sd_lavc.c` applies `sub-scale` (and `sub-pos`) to bitmaps whenever `sub-ass-override` isn't `no` — so in both `scale` and `force` — by stretching the bitmap from its centre with linear filtering: soft, thick edges, and nothing else of the style reaches it. `playback.SubScale` (both engines, under their state lock) holds `sub-scale` at 1 while the main track is a picture (`MainImageSubtitle` on the raw track-list) and restores the style's size for text; `sub-pos` still applies (lift to clear the controls). `State.subtitleSize` ignores the observed 1 then. HDR isn't the issue: vo_gpu draws subtitles as sRGB at 203 nits (`image-subs-hdr-peak` is gpu-next only). Frontend: `isPictureSubtitle`, `textInstead` (own text track in the language, same HI-ness, else an addon's); `smartSubtitle` = own text → addon → own picture (waits for addons before taking a picture); `autoSubtitle` counts only text tracks; the captions-on path switches mpv's picture pick to the file's own text track. Panel: "Image" badge (`trackLabel` adds "Image" elsewhere, `{image: false}` in the panel) and a Style-tab note with a "Use … text subtitles" button. ASS under Restyle (`force`): font, size, colour, edge, position apply; libass leaves inline tags (`{\c}`, italics) and positioned signs (`\pos`) alone, and `sub-bold` doesn't reach ASS styles (mpv sets no ATTRIBUTES bit). `strip` would flatten signs, so it isn't used. Fixture `internal/player/testdata/picture-subs.mkv` (PGS en SDH default + SubRip en) was made with a hand-written PGS writer (PIL + struct, ffmpeg can't encode PGS); a render-API shot tool (like `build/libmpv/smoke`, `glBindFramebuffer` before `glReadPixels`) compares looks.
- **Keys:** Shift+C, R/Shift+R, G/Shift+G are in `playerShortcuts`; `shiftedRepeating` is the new held-key map beside `shifted`. Not gated by the watch party ([[watch-party]]: gate covers pauses, seeks, speed).
- **Tests:** Go `secondary_test.go` (needs mpv; tracks.mkv has en/ja/Signs), `subtitle-position.test.ts`, `second-subtitles.test.tsx`, `subtitle-panel.test.tsx`. `Track` literals in tests need `secondary: false`; `profileSettings()` has `secondSubtitleLanguage`. routes/player.test.tsx's 16 stale tests stay stale.
