#123 (redesign epic [[redesign-epic]]) restyled the screens before a profile is in use. `components/account/focus-screen.tsx` holds `FocusScreen` (every one of welcome, sign-in, qr-sign-in, profiles uses it): `relative isolate -mt-(--titlebar-h) pt-(--titlebar-h) min-h-[calc(100%+var(--titlebar-h))]` with `<Ambient tone="brand" />`, so the glow runs under the `focus` chrome's title strip (its `<main>` pads by `--titlebar-h`), and the content column is `flex-1 justify-center` inside. It also exports `pillButton` (h-11 rounded-full, press scale) and `glassButton` (for `variant="ghost"`: `glass` plus `hover:bg-(--glass-regular)`, so the ghost hover doesn't replace the tint; a `hover:before:` wash marks it). Sign-in and QR are one `glass-thick rounded-3xl p-8` card each (Back button above it); the Input's height has to go on the inner input (`rounded-xl [&_input]:h-11 [&_input]:leading-11`), because `className` lands on the wrapper span.

**Why:** the user's Apple TV-style redesign wants the first-run screens to feel like the app, and these screens had no shared wrapper.

**How to apply:**
- Picker tiles: `tileLift` in `routes/profiles.tsx` (spring to 1.05× on hover/focus-visible, `motion-safe:`) goes on the `relative` span that holds avatar and pencil badge; the brand ring is `group-focus-visible:ring-brand` on the avatar, the current profile keeps `group-aria-current:ring-primary`. Dialog ring offsets in the editor use `ring-offset-transparent` (the dialog is translucent glass now, `ring-offset-popover` would show a seam).
- PIN: `PinField` keeps the read-only input but visually hidden (`unstyled className="sr-only"`, so the "PIN" textbox tests still work) and shows four `data-slot="pin-dots"` dots; `data-filled` marks the digits in. `shake` (a count, from `PinEntry`'s wrong-PIN counter) is the dots' `key`, so each wrong PIN restarts `motion-safe:animate-toast-error-odd` (±3px, subtle on purpose: the ticket says reuse those keyframes). Keys are `size-16 glass-thin` ghost buttons; glass inside the dialog's glass-thick blurs nothing (backdrop root) and reads as a tint. No `tabular-nums` on the digits: Mona Sans turns it into a slashed-zero look.
- `PinGate` (locked profile at launch) got the Ambient and a `glass-thick rounded-3xl` card but isn't in the screenshots: reaching it needs the app shell and a locked current profile.
- Contrast: two "PIN key digit" pairs added to `contrastPairs`. Muted text on the brand glow's peak (18 % brand over the page) is 4.6:1 in light: don't make the glow stronger without checking.
- Screenshot rig (not committed): `frontend/vite.shot.config.ts` aliasing `@bindings/<service>` to stubs whose `Service` is a Proxy answering `service.Method` from a handlers map keyed by `?scene=`/`?fail=`/`?qr=`/`?offline=`/`?wrongpin=` query params, `@/lib/platform` stubbed to "mac"; routes are hash URLs (`/?scene=picker#/profiles`), clicks via `Runtime.evaluate`. The QR path came from `rsc.io/qr` in a throwaway Go main. Nuvio's avatar catalog needs its anon key, so the shots use drawn SVG avatars. The root route redirects `#/sign-in?reason=…` oddly when `?scene` is in the real query; reach the session-ended page from `#/` with a session-ended account instead.
- Status (2026-11-06): built and committed on the worker branch, not pushed (Actions down); `pnpm test` not run yet. Tests to watch: `profiles.test.tsx` (new dots/shake case, ambient + badge case), `sign-in.test.tsx` (welcome pills, sign-in card), `qr-sign-in.test.tsx` (white tile in a glass card), `contrast.test.ts`.
