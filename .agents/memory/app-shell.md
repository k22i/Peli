#114 (redesign epic [[redesign-epic]]) turned `components/shell/` into: `#content` fills the window (`fixed inset-0`), padded by `ps-(--sidebar-inset) pt-(--titlebar-h)`; a `fixed` `glass-thick` sidebar (`start-2 top-2 bottom-2`, `w-60` from md, `w-16` rail below); a `fixed` title strip (`TitleBar`, `scrolled` prop from `useScrolled(pane)` in `app-shell.tsx`, also `data-scrolled` on `#content`). `--titlebar-h` comes from a class per platform (`titleBarHeight`), `--sidebar-inset` from classes on the shell root. `bleed` (index.css) cancels both for hero art; Gallery › Shell (`gallery/shell.tsx`) shows it. `scroll-edge-top` gained `--scroll-edge-cover` so the blur also covers a background-less bar (the title strip sets it to `--titlebar-h`). Window colour is now `--background` (`theme.ts`, `main.go`, `theme.test.ts`).

**Why:** the user's Apple TV/Music layout. Search is a field-like link first in the sidebar, then Home–Anime, then Library; only the look changed.

**How to apply:**
- Sidebar order is `visualOrder` in `sidebar.tsx`; ⌘1–6 still use `sections.ts`. Arrow keys and the roving Tab stop follow DOM order, so Search is index 0 and wrap-around goes Library → Search. The Search link's ⌘F `Kbd` is `aria-hidden` so its name stays "Search".
- Sidebar links use `activeOptions { exact: true, includeSearch: false }`, so a chip or filter (`?genre=`) keeps its section highlighted; a stubbed page at `/?x=1` is still Home. Sidebar and title bar have their own view-transition groups (above `content`) so a route change never hides them.
- The md breakpoint is 768px, so a 900×700 window still has the full panel; the rail shows below 768.
- Sticky things inside `#content` need `top-[calc(var(--titlebar-h)+…)]` (Settings nav does).
- Brand-on-active-sidebar pairs (over black/white, via `glass-thick` + `brand-soft`) are in `contrastPairs`; checked by hand with node (4.5/3.14+ dark, 5.05 light).
- Screenshot harness that worked: `frontend/vite.shot.config.ts` (throwaway) aliasing `@bindings/<name>` to scratchpad Proxy stubs (`Service` answers by `service.Method`, models re-exported from the real `models.ts` when one exists) and `@/lib/platform` to a stub reading the hash; real Cinemeta over the network; CDP script as in [[spike-ticket-workflow]]. Chrome needs ~7 s to start. `git stash` the tracked changes for the "before" shots.
- Built app: `wails3 task darwin:package` takes ~10 s; the window that paints is the second "Peli" id (the first is blank). osascript clicks and Option+Tab did not get past the welcome screen, so the native sidebar and traffic-light position were not checked (#114 open item).
- Tests weren't run (the user asked to skip them): `app-shell.test.tsx` (arrow order, nav order, scrolled), `theme.test.ts` and `contrast.test.ts` are the ones to watch.

## iOS floating tab bar (#129, 2026-11-17)

The compact shell's tab bar is a floating capsule (Home–Library) plus a round Search button beside it. On iOS 26+ it is **native** Liquid Glass over the webview; on iOS 17–25, in vitest and in stubbed shots it is `TabBar`'s CSS capsule with the same geometry. Search left the top strip (compact keeps only the wordmark and profile).

- **Bridge:** `internal/shell` (bound on every platform, methods only in `shell.go`; `shell_other.go` no-ops, `shell_ios.go` cgo → `tabbar_ios.m`). `SetTabBar(TabBarState{items, active, hidden, minimized, theme, search, placement})`, `TabBarHeight()` (62, 52 when the window is < 500 pt tall, 0 = no native bar). Native taps emit `shell:tab {id}`, `shell:search`, `shell:expand` (sent from a goroutine: emitting on the main thread can wait on it). `main_ios.go` calls `shell.UseWindow(window.NativeWindow)`; `build/ios/main.m` is untouched (the view is added lazily on the first `SetTabBar`, above Wails' `webView` in `WailsViewController.view`). `placement` is only "bottom" today; #138 can add "top" in `place`.
- **Native view (`tabbar_ios.m`):** `PeliTabBar` fills the controller's view, `pointInside:` is true only on the capsule and the circle, so taps elsewhere reach the webview. `UIGlassContainerEffect` (spacing 8) holds the capsule and Search `UIGlassEffect` views (interactive, `cornerConfiguration` capsule); the selection pill is a glass view inside the capsule; spring 0.35 s / damping 0.8, none under Reduce Motion. It hides itself on `UIKeyboardWillShow/Hide`. Theme = `overrideUserInterfaceStyle` from Peli's theme, with a 0.18 black tint on the glass in dark. Frames are computed in `place` from `safeAreaInsets` (no Auto Layout). Accessibility: tabs are buttons with Selected, then Search; `UILargeContentViewerInteraction` on the bar.
- **Frontend:** `lib/tab-bar.ts` (sections split, `sectionOf` keeps the last section on title/folder/person/settings pages, `nextScroll` 48 down / 24 up, `nativeTabBar.available`), `components/shell/use-tab-bar.ts` (`useTabBar` = model shared by both bars, `useNativeTabBar` pushes state per frame and maps events, `startNativeTabBar` probe run by `main.tsx` on iOS before the first render, ≤ 400 ms), `feature("nativeTabBar")` (the one iOS-only-true feature). Re-tap: off the section root → navigate to it; on it → `#content` scrolls to the top (smooth unless reduced motion) and the bar expands.
- **Hidden (composable):** the shell hides the bar on `chrome: "none" | "focus"` routes and at regular width (`shown` = compact and browsing chrome). Anything else calls `hideTabBar()` from `lib/tab-bar.ts` and calls the returned release when done; requests are counted, a double release counts once. #134's sheets should do exactly that (e.g. in an effect while open). The CSS bar also hides while `visualViewport` is > 120 px shorter than the window (keyboard); the native bar uses the keyboard notifications.
- **Insets:** `index.css` on `data-platform=ios`: `--tabs-h` (62px, 52px under 500 pt tall; native overrides it inline from `TabBarHeight`), `--tabs-bottom` = max(safe bottom − 12, 8), `--tabs-float` = h + bottom + 16. The content pane pads `pb-(--tabs-float)` at compact; `--spacing-tabs`/`h-tabs` are gone. #132 and other pages should pad by `--tabs-float`, never a fixed number.
- **Icons:** `build/ios/Assets.xcassets` (was a stray Contents.json file) holds `Tab<Label>.imageset` template SVGs, compiled by actool next to Wails' generated AppIcon catalog (both actool calls in `build/ios/Taskfile.yml`). `lib/tab-icons.test.tsx` fails when a section lacks one or the lucide glyph drifts; `UPDATE_TAB_ICONS=1` rewrites them.
- **Gotchas:** headless Chrome `--window-size=402,…` lays out wider than 402; use CDP `Emulation.setDeviceMetricsOverride` (mobile, dpr 2) for phone-size stubbed shots. A Search tap from the native button focuses the field from script, outside a webview gesture, so on a device (iPhone 14 Pro, iOS 27.2.1) the keyboard stayed down. Fix: `focus_ios.m` wraps WKContentView's private `_elementDidFocus:userIsInteracting:…` (every variant whose arguments are all integers/pointers, found by prefix at runtime) and passes YES for 1.5 s after the native Search tap, first focus only (`peli_focus_allow_keyboard`, installed on the first tap). If a WebKit update renames the selector, nothing breaks; the keyboard just stays down again. `TestIOSBuildLeavesOutTheDesktopOnlyPieces` already failed on main before #129 (iosplayer gained files); `TestIOSTabBarFiles` pins `internal/shell`'s files.
