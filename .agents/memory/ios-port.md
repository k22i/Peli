Phase 1 of the iOS port is on `main` (ADR-0055, audit in `docs/ios-port-audit.md`). Shell = Wails v3.1.0's experimental iOS target (the user chose it over the audit's gomobile bridge): same `main.go` services and unchanged React frontend, `wails://` scheme, iOS 17 minimum, iPhone + iPad, debrid only, libmpv player in Phase 5 (a separate spike lives in `spikes/ios-libmpv` and `build/libmpv`).

**Why:** the user accepted the experimental risk for the least bridge code; torrent, plugins, party, updates and firstmouse must stay out of the iOS binary (App Store review).

**How to apply:**
- `ios` implies `darwin`: macOS-only files need `//go:build darwin && !ios` (`secrets/native_darwin.go`, `player/*_darwin.*`). Go refuses C/ObjC files in a package with no cgo files, so the `.m/.c/.h` files in `internal/player` carry the constraint too.
- `main.go` = shared `peli` struct + `services(extras)`; `main_desktop.go` (`!ios`) adds updates/plugins/torrent/party/firstmouse/window; `main_ios.go` adds the window and lifecycle (`events.IOS.ApplicationDidBecomeActive` → `pullAndPush`, `DidEnterBackground` → `FlushProgress` in `IOS.BeginBackgroundTask`; TODO Phase 6: player's last report, monitor/timers across suspend). A new shared service goes in `newPeli`, a desktop-only one in `main_desktop.go`; never import the left-out packages from `main.go`.
- Seams: `internal/playback` (State, LoadOptions + `Valid`, Report, Watching, Gate, codes, `Engine`, `Sink`); `internal/player` aliases them in `types.go` and its mpv half is `!ios`; `service_ios.go` is the iOS `player.Service` (same methods, "not available yet" until `player.UseEngine`), parity checked by `TestIOSServiceHasTheDesktopMethods`. `secrets/native_ios.go` over `application.Mobile.SecureSet/Get/Delete` (WhenUnlockedThisDeviceOnly), tested through `mobile.go`. `store.DefaultPath()` uses `Mobile.StoragePath()` on iOS.
- Out-of-scope services are NOT bound on iOS: bound method ids hash package path + type + method, so stubs would pull `internal/plugins` etc. into the iOS deps. Calls fail "unknown bound method id". The frontend still calls updates/party at the root route and plugins when listing streams: Phase 2 needs an `isIOS` flag. Bindings are generated from the desktop only (iOS Taskfile passes no `-tags ios`).
- Boundary test: `ios_boundary_test.go` (`go list -deps` with `GOOS=ios GOARCH=arm64 CGO_ENABLED=1 -tags ios`, no SDK needed) plus a desktop twin. Accepted exception: Wails' own `pkg/application` imports `pkg/updater` on every platform (providers and `internal/updates` stay out).
- Build: `wails3 task ios:package` → `bin/ios/peli.app` (simulator, ad-hoc signed, arm64, ~16 MiB, ~65 s). Scaffolding is `build/ios/` (not a top-level `ios/`), `xcode/` is git-ignored and regenerated. `build/config.yml` has `ios:` (bundle id `k22i.net.peli`, version from `build/darwin/Info.plist`). Set `IOS_BIN_DIR`, not `BIN_DIR`, in the iOS Taskfile: a var set in an included Taskfile overrides the root's and sent the macOS build into `bin/ios`. No simulator runtime was installed, nothing has launched.
- Need `GOOS=ios` + cgo + SDK flags for `go build/vet` of iOS: copy the CGO_CFLAGS/LDFLAGS from `build/ios/Taskfile.yml` (`-isysroot $(xcrun --sdk iphonesimulator --show-sdk-path) -target arm64-apple-ios17.0-simulator`).
- Baseline failures that predate this work (don't chase): Go `anilistaddon TestMeta`, `backend TestPushUnsupported`, `player TestSecondarySubtitleControls`, `plugins TestCheerio`, `store TestFixtures/TestSettingsPersistPerProfile/TestImportWatched`, `tools/notices TestBuildLibmpv`, flaky `tracking TestAniListStatusRatingAndRemoval`; 60–62 vitest failures in 16 files (player/more-menu/speed-menu/subtitle-panel/picture-sheet, plugins-pane, ranking fakes/remembered, router, browse, gallery, library, player, profiles, search, settings, streams).
- Wails 3.1.0 upgrade notes: `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0` (replaces `~/go/bin/wails3`), `@wailsio/runtime` pinned to 3.1.0, bindings gain an `events/` dir, no code changes needed. Go here is 1.27.1; Wails recommends 1.27.3. Related: [[frontend-stack-preferences]], [[player-service]], [[libmpv-build]], [[auto-update]].

## Phase 2 (frontend, touch shell, first simulator run)

- **Platform flag:** Wails never injects `window._wails.environment` on iOS (3.1.0 does it for darwin/windows/linux only), so `System.IsIOS()` is always false there. `lib/platform.ts` `isIOS()` = `System.IsIOS()` or the `PeliIOS` user-agent token (`ApplicationNameForUserAgent` in `main_ios.go`; keep in step). `isTouch()`, `currentPlatform()` returns `"ios"`, `startPlatform()` sets `data-platform`/`data-touch` on `<html>`. Tests: `onIOS()` from `test/ios.ts` (setup mocks `@/lib/platform`, resets after each test).
- **Features:** `lib/features.ts` `feature(name)` is the one list (updates, party, plugins, torrent, miniPlayer, playerPanels, hdr, commandPalette, people, multiSelect, gallery). Read it at call time, never at import. Unbound-service call sites skip (`enabled`, effects, `StreamFeed` drops link-less torrents, `resolvePick` skips torrents, `Party.Watch` in the player). A disabled TanStack query stays `isPending`: don't `loading: isPending` on it (`usePluginTargets`). `settingsPanes` became `visiblePanes()` (no Plugins on iOS). `ios.test.tsx` fails any call to updates/party/plugins/torrent. Kept on iOS: skip intros/markers, next episode, tracking, max resolution.
- **Shell:** `lib/shell-mode.ts` `useCompactShell()` = iOS and (width < 700 or height < 500), live via matchMedia (iPhone portrait/landscape, iPad narrow split view). Compact: `tab-bar.tsx` (Home, Movies, Shows, Anime, Library; glass `material-bar`, `--spacing-tabs`) + a top strip with wordmark, round Search and the profile; regular: the existing top bar (there is no sidebar any more, the #114 sidebar was replaced in the revamp). `pointer-coarse:` bumps nav/profile to 44 pt, `hit-area` utility for chips, row/rail arrows hidden on coarse (swipe), long-press opens Base UI context menus (verified in source, not on device).
- **Safe areas:** Wails lays the WKWebView out INSIDE the safe area (`viewDidLayoutSubviews`), measured: iPhone 17 webview 402x778 of 874, `env(safe-area-inset-*)` = 0, bands outside show the window colour. So heroes/video can't bleed under the status bar or home indicator without changing the webview frame (Phase 5: the spike's `NativeWindow()` + KVC `webView` route). Landscape iPhone is also inset left/right by the island. Page CSS still uses `env()` + `viewport-fit=cover` so it works if the frame changes.
- **Launch gotchas:** iOS 27 SDK needs the UIScene life cycle: `build/ios/main.m` has `PeliSceneDelegate` (makes a UIWindow on the scene, hands it to `WailsAppDelegate.window` via KVC, forwards active/background callbacks since app-delegate ones stop), plus `UIApplicationSceneManifest` in both Info plists; built and launched WITHOUT the SDK-18 stamp. The link task uses `build/ios/main.m`, not the copy in `xcode/` (that one is regenerated and lacks the shim). Simulator keychain gave -34018 until `entitlements.simulator.plist` was linked in as a `__TEXT,__entitlements` section (`codesign --entitlements` makes the simulator refuse to launch). `UIDeviceFamily` 1,2 added (iPad ran as a scaled iPhone app). Production builds compile out Go console logs: use `ios:compile:ios` (debug) and `log show --predicate 'process == "peli"'`; the asset server logs every request, so a throwaway `fetch("/__dbg/<msg>")` is a console.
- **ATS finding:** the webview's `fetch` to https works (Cinemeta 200, ES modules, the ranking Web Worker, all over `wails://`). `http://` to an IP literal works; to a domain it fails ("Load failed") unless `NSAllowsArbitraryLoadsInWebContent` (works) or a per-domain exception is set. `NSAllowsArbitraryLoads=true` alone did NOT lift it in the webview. Go's `net/http` is not subject to ATS: `Addons.Fetch` answered http://localtest.me 200, and the addon client already falls back to it on a TypeError, so http addon JSON works with strict ATS (release Info.plist has `NSAllowsArbitraryLoads` false). Left: http `<img>` posters from http addons. Proposed: ship strict, accept broken http images or proxy them through Go; `NSAllowsArbitraryLoadsInWebContent` is the narrowest plist switch (web content only, needs an App Review justification), never the blanket key.
- **Transparency:** `Window.SetBackgroundColour(r,g,b,a<255)` sets `webView.opaque = NO` and a clear/alpha background (Wails `ios_window_set_background_color`); `lib/theme.ts` calls it with alpha 255 and the shell paints `bg-background`, so Phase 5's player route must call it with alpha 0 (`chrome: "none"` already paints nothing) and the video view goes under the webview in the same window.
- **Simulator recipe:** own devices (`xcrun simctl create peli-p2-iphone …iPhone-17`, `peli-p2-ipad …iPad-Pro-11-inch-M5-12GB`, runtime iOS-27-2); `wails3 task ios:compile:ios` then bundle as `ios:run` does but with the UDID instead of `booted` (build, `Info.dev.plist`, actool, ad-hoc codesign, `simctl install/launch`); `simctl io <udid> screenshot`. There is no Simulator.app here (no rotate/split view by hand): rotate with `application.IOS.SetOrientation` from a debug Go hook. Split view could not be exercised; the breakpoint is a media query tested in jsdom. Screenshots are in `docs/ios/phase2-*.png`. The machine was at load ~700 from other workers: vitest timeouts (session, accuracy, many 1 s `findBy`) are load flakes, rerun those files alone.
- **Open for Phases 3–5:** page layouts on a phone (hero buttons stack, rows are desktop sizes, Settings two-column below 768), http poster images, the player route (transparent webview, full-bleed frame, touch controls, `playerPanels` still hidden only in Settings), sign-in/OAuth redirects (`Browser.OpenURL`), `ios:package` Xcode project (`xcode/` copy of main.m), production `DisableInspectable`.
**UIScene (ADR-0056, 2026-11-13):** iOS 27 SDK apps must use scenes. `build/ios/main.m`'s `PeliSceneDelegate` (manifest in both Info plists) gives Wails' delegate a window on the scene (`setValue:forKey:@"window"`) and calls its `applicationDidBecomeActive:` family from the `scene*` callbacks; Wails is untouched, the Taskfile links `build/ios/main.m` and there is no SDK-18 stamp (`vtool -show` says sdk 27.2). Every Wails iOS helper reads `appDelegate.window`, so they follow it (audited `application_ios.m`, `mobile_features_ios.m`, `webview_window_ios.m`; no `keyWindow`/`UIApplication.windows`). An iOS-only Wails patch with `-modfile=go.ios.mod` was built and verified too, then dropped; it lives on branch `k22i/ios-uiscene-wails-patch`. Launch check after a Wails upgrade: app starts, webview shows, Active/Background events arrive, dialog opens. Simulator gotchas: `simctl launch` of Settings can take minutes when the host is loaded; `GetOrientation` does not exist on `application.Mobile` in 3.1.0; ObjC in a `.go` cgo preamble breaks the bindings generator (use a `.m`); a probe goroutine can register `OnApplicationEvent` right after `application.Get()` is non-nil and catch the first events. iPad simulator ignores `SetOrientation`. Related: [[ios-port]].

## Phase 3 (auth: sign-in, Keychain, profiles, PIN, kids) — 2026-11-13, ADR-0057

- **Sign-in on iOS:** email + password as on desktop (16 px fields, `inputMode=email`, no autocorrect; the global coarse-pointer 16 px rule loses to `[&_input]:text-[0.9375rem]`, so the sign-in `fieldClass` has `pointer-coarse:[&_input]:text-base`). The QR route is "Sign in on the web" on iOS: no QR image, an "Open the sign-in page" button opens the same device-login URL in Safari, Go keeps polling. Welcome and sign-in say "Sign in on the web". `thisDevice()` in `lib/platform.ts` replaces "this computer".
- **Wails' `Browser.OpenURL` does not work on iOS:** the runtime handler is `internal/browser` → `exec.Command("open")`. Use `lib/open-url.ts` `openURL()` (iOS → `appinfo.Service.OpenURL` → `application.Mobile.OpenURL` = `UIApplication openURL:`, i.e. Safari; others → Browser.OpenURL). Done for qr-sign-in, tracking-dialogs, addon-dialogs; `title-page.tsx` (trailer) still calls `Browser.OpenURL` (Phase 4's file).
- **Keychain class:** Wails' `SecureSet` hard-codes WhenUnlockedThisDeviceOnly (no option). `internal/secrets/keychain_ios.go` is Peli's own cgo `SecItem*` (service `k22i.net.peli.secrets`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`); the boundary test allows exactly that one cgo file. Verified in the simulator keychain db (`~/Library/Developer/CoreSimulator/Devices/<udid>/data/Library/Keychains/keychain-2-debug.db`, `select pdmn from genp`: `cku` = AfterFirstUnlockThisDeviceOnly; the session items vanish on sign-out). No migration from Wails' items. Keychain survives `simctl uninstall`: use `simctl keychain <udid> reset` for a clean start.
- **PIN/kids on touch:** the keypad is the input (`PinField` input is read-only, so no keyboard covers the dots); keys are 64 pt. Kids toggle works; leaving/changing asks for the parent PIN ("Ask a parent"). `Switch` got `hit-area` (44 pt). The profile menu hides its ⌘, hint on touch (`top-bar.tsx`'s ⌘F hint is Phase 4's).
- **Dev rig (not shipped):** build tag `pelidev` (`dev_ios.go`, off-stub `dev_ios_off.go`): `SIMCTL_CHILD_PELI_DEV_DIR` → drop `cmd.js` there and it runs in the webview (`fetch("/__dev/out",{method:"POST",body})` appends to `out.txt`); `SIMCTL_CHILD_PELI_DEV_EMAIL/PASSWORD` sign in once at launch (never logged). Build with `wails3 task ios:compile:ios EXTRA_TAGS=pelidev` (new Taskfile var), then wrap as the `run` task does (`.dev.app`, bundle id `k22i.net.peli.dev`). `PELI_NUVIO_URL` via `SIMCTL_CHILD_` points the app at a fake `nuviotest` server (throwaway test serving it on 127.0.0.1; set `pin_enabled:true` in the profile JSON or the picker won't lock it). Router is hash-based: `location.hash="#/profiles"`. PIN keys typed from JS need ~400–600 ms between presses or the dialog stalls.
- **Live account (2026-11-13):** only sign in and sign out (Keychain items checked before/after; no PIN, profile or kids writes). Everything else ran against the fake server.
- **Open for Phases 4–6:** the hero text has no scrim on bright art (phone), the Home top strip's search/profile sit over the hero, ⌘F hint in the search field and the trailer `Browser.OpenURL` (Phase 4); background push with a locked device (Phase 6) can now read the session.

## Phase 4 (browsing: Home, Browse, Search, Title) — 2026-11-13

- **Variants:** `ios-compact` (iOS and compact width, same query as `compactQuery`) and `ios-short` (iOS and height < 500, iPhone on its side) in `index.css`; both need `data-platform="ios"`, which was never set before: `currentPlatform()` ignored the `PeliIOS` user-agent token (fixed). Desktop never matches.
- **Card sizes:** `--container-poster/-landscape` are 10/17 rem on iOS (iPad: 4 posters across portrait), 9.25/15 rem at compact (grid 2 columns, rows show 2.3 cards). `cardWidthRem(shape)` in `row.tsx` reads the variable (the `cardRem` constants are the fallback), used by the virtualizer and `PosterGrid`.
- **Phone layout:** Home hero `ios-compact` 64vh, actions in one row (Surprise me is a glyph), dots under the text; episode rows are a 128 px still beside the text with no big number, estimate 124 px; Browse and Episodes sticky headers go static at `ios-short`; search field has no ⌘F hint on touch, search keyboard hints, 44 pt clear button. Long-press on a card opens TitleMenu (checked with synthetic `touchstart`, 500 ms); episodes have a visible ⋮.
- **http images:** `<img src="http://domain/…">` fails in the webview (ATS stays strict, confirmed: https loads, http errors). `viaProxy()` in `lib/artwork-url.ts` sends them to `/__image?url=` served by `imageproxy_ios.go` (Go `net/http`, http: only, image/* only, 8 MiB, 15 s) wrapped around the asset handler. Used by Artwork, hero Logo and the addon row logo. The user's real addons are all https (7) plus the `peli://` built-in, so it was tested with httpbin only.
- **TMDB:** the key lives in the Keychain through `secrets` (Phase 1 `native_ios.go`); on iOS it has to be typed or pasted into Settings (the key is deliberately not synced). No key was available, so cast/crew art was not seen live; without a key the About card shows names as text. Person links already degrade through `feature("people")`; multi-select through `feature("multiSelect")`. Trailer uses `lib/open-url.ts`.
- **Rotation:** portrait ↔ landscape round trips (including six in a row, with the page scrolled) always came back to 402×778 / 750×382; the 278 px reading did not reproduce on iPhone 17 with `SetOrientation`. iPad ignores `SetOrientation`; split view was not exercised.
- **Memory:** iPhone WebContent ~200 MB after Home → Browse → Search → two titles; nothing heavy seen. No long-scroll harness was run.
- **Rig:** the Phase 3 `pelidev` rig works; this phase used a private throwaway (file-polled `ExecJS`, orientation, sign-out, `SIMCTL_CHILD_` env), never committed. Both sims were driven with one shared JS file; the machine ran at load ~660, so screenshots lag 10+ s after navigation. Screenshots: `docs/ios/phase4-*.png`.
- **Open:** kids allow-list not exercised on iOS (no kids profile, writes); on-screen keyboard behaviour not seen (simulator uses the hardware keyboard); split view; tests for `cardWidthRem`, `viaProxy` and the proxy not written (tests are deferred, [[tests-later]]).

## Phase 5 (debrid playback with libmpv) — 2026-11-13, ADR-0058

- **Engine:** `internal/iosplayer` (engine.go, mpv.go, host_ios.m/.h) behind `player.UseEngine` in `main_ios.go`; shared mpv rules in `internal/playback/mpvprops.go`. Packaging: `ios:libmpv` reuses `build/libmpv/.work/libmpv.xcframework`, `embed:libmpv` signs it into `Peli.app/Frameworks`. Simulator `.app` 36 MB (16 MB executable + 20 MB framework), 16 MB zipped. Engine details and the hwdec/8-bit rules: [[ios-libmpv]].
- **Touch player:** the desktop route adapted (`isTouch()`, `feature("desktopControls"|"streamSwitcher"|"playerPanels")`). The root used to wake the controls on every pointerdown, so a tap could never show them (fixed: a touch on the picture is left to `tapPicture`). On iOS the picker → player navigation uses `replace`, so Back lands on the title. The player screen calls `keepWindowClear()` (`lib/theme.ts`): any `Window.SetBackgroundColour(…,255)` while the video host is attached makes the webview opaque and hides the picture.
- **Rig (scratchpad, not in git):** `launchk.sh` relaunches the dev app on the signed-in account (no `PELI_DEV_GUEST`); `PELI_DEV_PLAY`/`PELI_DEV_START` play a URL with no watching item (no Nuvio writes); `PELI_HWDEC` forces the start mode; the shared `$PELI_DEV_DIR/cmd.js` is read by EVERY running dev app, so terminate one simulator's app before driving the other. Under host load 300–600 a `js.sh` round trip takes seconds: do time-critical clicks (the 10 s "Start over" prompt) inside one page-side script that polls and clicks. Synthetic taps need pointerdown + pointerup + click with `pointerType:"touch"`; the seek bar is `[data-testid=seek-bar]`.
- **Live runs (2026-11-13):** the user signed in on `peli-p5-iphone` and asked for their own profile, so Debrid came from their own addon (Meteor, same TorBox account). Breaking Bad had real history there, so the flow used an untouched show (Chernobyl); undo = episode menu "Mark unwatched" (watched already cleared the progress); checked with a fresh pull plus an empty outbox (`store.Pending` on a copied `peli.db`, read with a throwaway tool). No trackers were connected on that device. Next-episode preparation resolves E2 ahead, which adds it to TorBox too. TorBox cleanup: `POST /v1/api/torrents/controltorrent {"torrent_id":N,"operation":"delete"}` works now (it was blocked by the classifier in October); delete only what the runs added (diff against a `mylist` baseline taken before).
- **Open for Phase 6 and a device run:** background playback and the last report on backgrounding, lock-screen/Now Playing (`SetNowPlaying` is a no-op), PiP (impossible on GLES), audio interruptions; on a device: zero-copy with `nv12`, the copy fallback, frame rate, the 8-bit conversion's CPU cost, integer textures. Picker labels user addons' link-bearing streams "P2P" when the addon's cache marker isn't recognised (Meteor), a desktop-shared quirk. The guest profile has no audio language, so default-flagged Russian/Hindi tracks start first.


## Phase 6 (suspension, interruptions, offline, trackers) — 2026-11-13, ADR-0059

- **Wails' `events.IOS.*` application events never arrived** under the scene delegate (and are queued to a goroutine anyway): Phase 5's `ApplicationDidBecomeActive`/`DidEnterBackground` handlers had never run. Lifecycle is now UIKit notifications observed in `host_ios.m` → `iosplayer.OnLifecycle` (WillResign → `Engine.Suspend`: park GL, pause, final Report saved by the sink, all before returning; DidBackground → bg task, Suspend again, `FlushProgress` + `tracking.Drain`; DidActive → `Resume`, `pullAndPush`, `syncer.WakeOf`, `tracking.Kick`). Background audio / Now Playing stay deferred.
- **Interruptions/route loss** pause and report (`pauseNow`); interruption end never auto-resumes. Rig: `PELI_DEV_DIR/audio` file posts the system notifications.
- **Verified in sims (fake Nuvio/SIMKL/AniList via `tools/iosrig`, build tag `rig`, run as a go test):** background mid-play → paused report reaches Nuvio; offline + background + `simctl terminate` → relaunch pushes progress and watched; SIMKL stop at 91 % queued offline, sent after relaunch; offline pill on iPhone; Start over (needs the fast JS flow: the 10 s prompt outlives only a single in-webview script; js.sh round trips take ~20 s); iPad: same bg/kill/offline runs. `kill -STOP/-CONT` imitates a suspend (sims never suspend).
- **AniList:** `ASWebAuthenticationSession` sheet (`internal/iosauth`, `appinfo.OpenSignInPage`), app stays active, loopback answers; system prompt needs a tap unless `PELI_AUTH_EPHEMERAL=1`. `PELI_SIMKL_URL`/`PELI_ANILIST_URL` test seams.
- **Rig gotchas:** use fresh `peli-p6-*` sims for fakes (the real-account sim `peli-p5-iphone` keeps its Keychain session; `simctl uninstall` doesn't clear Keychain); `launch.sh`/`launchlive.sh`/`d.sh` live in the session scratchpad (play/ctl/audio files in `PELI_DEV_DIR`, commands incl. simkl-connect, ani-connect, check, undo, tracker). Live Nuvio run: Chernobyl S1E1 via the local clip, progress + watched reached Nuvio, undone with `undo` (UnmarkWatched + RemoveProgress), fresh pull showed watched=0, pending=0. Live SIMKL later ran (2026-11-13, user approved a fresh code): scrobble at 91 % landed, `tracker none` removed it, `disconnect` revoked; the title list is cached 5 min, so relaunch before re-reading it. A live play also writes Nuvio progress/watched: undo with `undo <id> - -` for a film. AniList live not done.
- Owed for a device: GL park really prevents the kill, OS-delivered interruptions, VideoToolbox zero-copy.
