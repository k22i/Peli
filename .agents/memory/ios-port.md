Phase 1 of the iOS port is on `main` (ADR-0055, audit in `docs/ios-port-audit.md`). Shell = Wails v3.1.0's experimental iOS target (the user chose it over the audit's gomobile bridge): same `main.go` services and unchanged React frontend, `wails://` scheme, iOS 17 minimum, iPhone + iPad, debrid only, libmpv player in Phase 5 (a separate spike lives in `spikes/ios-libmpv` and `build/libmpv`).

**Why:** the user accepted the experimental risk for the least bridge code; torrent, plugins, party, updates and firstmouse must stay out of the iOS binary (App Store review).

**How to apply:**
- `ios` implies `darwin`: macOS-only files need `//go:build darwin && !ios` (`secrets/native_darwin.go`, `player/*_darwin.*`). Go refuses C/ObjC files in a package with no cgo files, so the `.m/.c/.h` files in `internal/player` carry the constraint too.
- `main.go` = shared `peli` struct + `services(extras)`; `main_desktop.go` (`!ios`) adds updates/plugins/torrent/party/firstmouse/window; `main_ios.go` adds the window and lifecycle (`events.IOS.ApplicationDidBecomeActive` → `pullAndPush`, `DidEnterBackground` → `FlushProgress` in `IOS.BeginBackgroundTask`; TODO Phase 6: player's last report, monitor/timers across suspend). A new shared service goes in `newPeli`, a desktop-only one in `main_desktop.go`; never import the left-out packages from `main.go`.
- Seams: `internal/playback` (State, LoadOptions + `Valid`, Report, Watching, Gate, codes, `Engine`, `Sink`); `internal/player` aliases them in `types.go` and its mpv half is `!ios`; `service_ios.go` is the iOS `player.Service` (same methods, "not available yet" until `player.UseEngine`), parity checked by `TestIOSServiceHasTheDesktopMethods`. `secrets/native_ios.go` over `application.Mobile.SecureSet/Get/Delete` (WhenUnlockedThisDeviceOnly), tested through `mobile.go`. `store.DefaultPath()` uses `Mobile.StoragePath()` on iOS.
- Out-of-scope services are NOT bound on iOS: bound method ids hash package path + type + method, so stubs would pull `internal/plugins` etc. into the iOS deps. Calls fail "unknown bound method id". The frontend still calls updates/party at the root route and plugins when listing streams: Phase 2 needs an `isIOS` flag. Bindings are generated from the desktop only (iOS Taskfile passes no `-tags ios`).
- Boundary test: `ios_boundary_test.go` (`go list -deps` with `GOOS=ios GOARCH=arm64 CGO_ENABLED=1 -tags ios`, no SDK needed) plus a desktop twin. Accepted exception: Wails' own `pkg/application` imports `pkg/updater` on every platform (providers and `internal/updates` stay out).
- Build: `wails3 task ios:package` → `bin/ios/peli.app` (simulator, ad-hoc signed, arm64, ~16 MiB, ~65 s). Scaffolding is `build/ios/` (not a top-level `ios/`), `xcode/` is git-ignored and regenerated. `build/config.yml` has `ios:` (bundle id `k22i.net.peli`, version from `build/darwin/Info.plist`). Set `IOS_BIN_DIR`, not `BIN_DIR`, in the iOS Taskfile: a var set in an included Taskfile overrides the root's and sent the macOS build into `bin/ios`. No simulator runtime was installed, nothing has launched.
- Need `GOOS=ios` + cgo + SDK flags for `go build/vet` of iOS: copy the CGO_CFLAGS/LDFLAGS from `build/ios/Taskfile.yml` (`-isysroot $(xcrun --sdk iphonesimulator --show-sdk-path) -target arm64-apple-ios17.0-simulator`).
- Baseline failures that predate this work (don't chase): Go `anilistaddon TestMeta`, `backend TestPushUnsupported`, `player TestSecondarySubtitleControls`, `plugins TestCheerio`, `store TestFixtures/TestSettingsPersistPerProfile/TestImportWatched`, `tools/notices TestBuildLibmpv`, flaky `tracking TestAniListStatusRatingAndRemoval`; 60–62 vitest failures in 16 files (player/more-menu/speed-menu/subtitle-panel/picture-sheet, plugins-pane, ranking fakes/remembered, router, browse, gallery, library, player, profiles, search, settings, streams).
- Wails 3.1.0 upgrade notes: `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0` (replaces `~/go/bin/wails3`), `@wailsio/runtime` pinned to 3.1.0, bindings gain an `events/` dir, no code changes needed. Go here is 1.27.1; Wails recommends 1.27.3. Related: [[frontend-stack-preferences]], [[player-service]], [[libmpv-build]], [[auto-update]].
