Epic #106 (ADR-0045), built 2026-11-05: the Anime tab is filled by Peli's own AniList addon, and anime with IMDb ids is left out of Movies and Shows.

**Why:** the user wants AniList preferred over Kitsu for lists and details, and chose an addon over a built-in catalog source ("not sure yet how to feel about" a non-addon source). Stream addons only take `kitsu:`/`tt` ids, so items carry the mapped Kitsu id; unmapped ones keep `anilist:` and show "No streams yet" (user's choice).

**How to apply:**
- Built-in addons (#107): URL `peli://<name>/manifest.json`; `addons.Service.Register(name, http.Handler)` answers them in `Fetch`; the TS client sends `peli://` straight to `fetchViaGo` (`isBuiltinAddon`). `store/builtins.go`: `SyncedAddons` (backend push strips list and base), `keepBuiltins` (pull keeps them in place), `offerBuiltins` (before the first URL containing "kitsu", else last; `builtins-offered` key so removal sticks). Offering only happens after `Store.UseBuiltins(Builtins)` (store.Service startup), so test stores get none and old tests' exact addon lists still hold.
- AniList addon (#108): `internal/anilistaddon` (catalog.go lists/ids, meta.go details + Kitsu `kitsu.app/api/edge` episodes), `anilist.Client.Public` for token-less queries, `animelist.List` shared with tracking in main.go and warmed at startup. In-memory cache (30 min lists, 6 h meta), x/time/rate limiter, 503 while AniList's Retry-After runs.
- Leaving anime out (#109): `animelist.Service.IMDbIDs` → `animeIdsQuery`/`useLeaveOutAnime` (`lib/anime.ts`); applied in browse `CatalogGrid` (asks the next page itself when a page adds nothing, up to 20), Home rows/hero (not anime catalogs), `searchGroups(answers, leaveOut)`. Setting `animeInMoviesAndShows` in Settings › Addons. `src/test/setup.ts` mocks `@bindings/animelist` globally (none are anime); override with `vi.mocked(AnimeList.IMDbIDs)`.
- #128 (2026-11-18) changed the lookups: `animelist.List` has a `load` lock for reading/downloading and `mu` for the maps only, so nothing waits behind a download; `Peek()` answers at once and loads in the background; `OnlyWhen(allow)` (iOS: `!iosshell.Cellular()`) gates the downloads that can wait (Warm, Peek), while Find/IsAnime/ByAniList still download. A week-old copy refreshes in the background (the old refresh test expected it inline). `Service.IMDbIDs` is gone: `LeaveOut(ids)` and `PosterTitles(ids)` (now `Titles`) answer a page at a time with `ready`; on the desktop they wait for the list (as before), on iOS they peek (`List.ready`). The addon's `idOf` waits on the desktop only (`waitForList`); on iOS unmapped answers keep `anilist:` ids and are cached 1 min; burst 4 on iOS. Frontend: `lib/anime.ts` keeps the sync `(id) => boolean` API over a session map filled by batched `LeaveOut` (`lib/batch.ts`), re-asked every 30 s while not ready; `resetAnimeAnswers()` runs after each test; mark test anime with `animeIds` from `test/anime.ts` (setup's `LeaveOut` mock reads it).
- "Posters for Anime", now "Anime titles" (`ProfileSettings.animePosterAddon`, Settings › Addons & content › Artwork) is per device, like every ProfileSettings field: nothing syncs it. The user saw Xperience posters on the Anime tab on the Mac but AniList covers on the iPhone and iPad (2026-11-18): the Mac had it set to Xperience, the phone and iPad had it Off. Not a bug; it has to be set on each device. On iOS, `Titles` answers "not ready" until the anime list is there (Wi-Fi only at launch), so cards keep AniList's covers until then.
- Follow rule (2026-11-20, ADR-0062, supersedes the poster-only rule from `3959beb`): with a poster addon chosen ("Anime titles" in Settings), Anime tab cards become the IMDb title they belong to (`animelist.Service.Titles` → `{imdb, type, season}`; `lib/anime-titles.ts` `useFollowAnime`/`followAll`/`useAnimeCard`, `AnimeTitleCard`). Any season but 0 of a show folds into the show; a film with its own IMDb id (decided by `Entry.TMDB`, parsed from `themoviedb_id`) is a movie; season-0 specials/films stay AniList's. Applied to the browse grid (page held until answered), Home rows, search + palette (`searchGroups` third arg), not the hero. The user's examples that drove it: Reincarnated as a Sword 2, Apothecary Diaries 3, Cyberpunk: Edgerunners 2 (later seasons). Test mock is `Titles` in `src/test/setup.ts`.
- New ProfileSettings fields must be added to the test fixtures in `lib/player.test.ts`, `routes/player.test.tsx` and `routes/settings.test.tsx`, or `vp check` fails.
- `go build .` drops a `peli` binary in the repo root; delete it.
